1. RESUMEN EJECUTIVO
===============================================================================================

QUÉ ES
  Contafi es un software contable para Colombia que se instala en Windows, trabaja sobre una base
  de datos local y se sincroniza con la nube. Sigue funcionando sin internet y después de cortes
  de energía, e incluye un asesor de IA que corre en el propio PC.

PARA QUIÉN
  Contadores independientes y firmas contables pequeñas que llevan la contabilidad de varias
  empresas (micro y pequeñas empresas, NIIF Grupo 2 y Grupo 3).

POR QUÉ LO ELEGIRÍAN
  - Un solo programa multi-empresa pensado para el contador. La competencia cobra por empresa.
  - Funciona sin internet y resiste cortes de luz.
  - Contabilidad automática a partir de las facturas electrónicas (XML de la DIAN).
  - Asesor de IA local: sin costo por consulta y sin enviar datos de clientes a terceros.

MODELO DE NEGOCIO
  Suscripción mensual o anual por contador, con un paquete de empresas incluido.
  Desde $119.000 al mes (antes de IVA). Detalle en la sección 17.

TIEMPO ESTIMADO (una persona a tiempo completo)
  - Unos 7–8 meses hasta empezar el piloto.
  - Unos 10 meses hasta terminar el piloto (dos cierres mensuales reales).
  - Unos 11–12 meses hasta el lanzamiento comercial.
  A medio tiempo, casi el doble.

COSTO FIJO DE OPERACIÓN AL INICIO
  Unos US$80 al mes (Supabase Pro, Vercel Pro que ya pagas, dominio y respaldos), más el
  certificado de firma de código anual. Detalle en la sección 18.

===============================================================================================

ARCHIVOS

    (ya con el rediseño Liquid Glass).
  - Respaldo del original: "... (respaldo antes del rediseño).html", en la misma carpeta.
  - Lienzo de diseño: https://claude.ai/artifact/WFLurEJZzxDWHAi1NAdey7

QUÉ SE REUTILIZA
  - El sistema visual: tokens de color claro/oscuro, tipografía Geist + Geist Mono, componentes,
    modo "reducir transparencia".
  - La lógica del motor como especificación funcional:
      postEntry, approveEntry, annulEntry        -> comprobantes, aprobación y anulación
      createSalesInvoice                         -> venta con IVA y costo de ventas
      createPurchaseBill                         -> compra con costo promedio ponderado
      registerCollection, registerPayment        -> recaudos y pagos
      registerCashMovement                       -> movimientos de tesorería
      trialBalance, incomeStatement, balanceSheet -> reportes
      cierres de período, auditoría, matriz de permisos (PERMS)
  - El PUC semilla y los datos de demostración.

QUÉ NO SIRVE PARA PRODUCCIÓN (HAY QUE REHACERLO)
  - Los datos viven en el localStorage del navegador: se pierden al limpiarlo y no tienen respaldo.
  - Permisos y contraseñas se validan en el cliente; las contraseñas se guardan en texto plano.
  - Cualquiera puede alterar saldos o comprobantes desde la consola del navegador.
  - Los montos usan números de punto flotante y se redondean a pesos enteros.
  - La numeración de comprobantes no controla que dos equipos pidan el mismo número.
  - Error de fechas: todayISO() usa toISOString() (hora UTC). Después de las 7:00 p. m. en
    Colombia registra la fecha del día siguiente. Hay que usar la zona America/Bogota.
  - Faltan retenciones, tarifas múltiples de IVA, notas crédito y débito, y cierre anual.

3. NICHO, PROPUESTA DE VALOR Y VALIDACIÓN
===============================================================================================

HIPÓTESIS
  Los contadores independientes que llevan entre 5 y 50 empresas pierden muchas horas pasando
  facturas a mano, pagan licencias de escritorio caras o dependen de que cada cliente pague una
  suscripción. Pagarían por un programa multi-empresa que:
  - funcione sin internet,
  - contabilice automáticamente las facturas electrónicas,
  - les avise de vencimientos y problemas de todas sus empresas en un solo lugar.

MENSAJE COMERCIAL
  "Lleva todas tus empresas en un solo programa, aunque se vaya el internet, con un asesor de IA
  que no manda tus datos a nadie."

VALIDACIÓN (FASE 0)
  - Entrevistar 8–10 contadores (guion en la Fase 0 de la sección 15).
  - Criterio de éxito: al menos 5 de 10 pagarían $119.000 al mes o más y 3 aceptan ser piloto.
  - Si no se cumple: ajustar el nicho (por ejemplo, vender directo a pymes) ANTES de construir.

6. ARQUITECTURA TÉCNICA
===============================================================================================

6.1 DIAGRAMA

  PC CON WINDOWS — Contafi (aplicación de escritorio Tauri)
   ├─ Interfaz React + TypeScript (diseño Liquid Glass)
   ├─ Motor contable (paquete TypeScript compartido)
   ├─ SQLite local cifrado (SQLCipher)        <- se trabaja aquí, con o sin internet
   ├─ Cola de sincronización (outbox)         <- lo pendiente de subir
   ├─ IA local: llama.cpp + modelo GGUF       -> consulta el motor mediante herramientas
   └─ Actualizador automático firmado
                 ⇅  HTTPS cuando hay conexión
  NUBE
   ├─ Supabase: Postgres (fuente oficial), Auth + MFA, RLS, Storage
   ├─ Vercel Pro: API de sincronización, importación de XML, PDF/Excel, cobros,
   │              actualizaciones, sitio web y versión web opcional
   └─ Proveedor tecnológico DIAN (facturación electrónica, versión 2)

6.2 TECNOLOGÍAS
  App de escritorio  Tauri 2 (instalador NSIS/MSI; usa WebView2, incluido en Windows 10/11).
  Interfaz           React + TypeScript + Vite. TanStack Query (datos), TanStack Table (tablas
                     grandes, virtualizadas), react-hook-form + zod (formularios y validación),
                     Chart.js (gráficas).
  Base local         SQLite con SQLCipher, accedida desde Rust (rusqlite) mediante comandos de
                     Tauri. La llave de cifrado se protege con Windows DPAPI (ligada al usuario
                     de Windows).
  Motor contable     Paquete TypeScript puro (@contafi/motor), sin acceso a disco ni red. Lo usan
                     la app y el servidor.
  Dinero             Enteros en centavos (bigint) o decimal.js. NUNCA el tipo number de
                     JavaScript para montos.
  Servidor           Supabase (Postgres, Auth con MFA, RLS, Storage). API en Vercel (Next.js,
                     route handlers) para sincronización, importación de XML, generación de
                     PDF/Excel, webhooks de pagos y publicación de actualizaciones.
  Tareas programadas Vercel Cron: respaldos lógicos, alertas, recordatorios de vencimientos,
                     renovaciones de suscripción.
  IA local           llama.cpp (llama-server) como proceso auxiliar en 127.0.0.1; modelo GGUF
                     cuantizado; sqlite-vec para búsqueda semántica.
  Otros servicios    Sentry (errores de la app y del servidor), Resend (correos), pasarela de
                     pagos colombiana con cobro recurrente (Wompi o ePayco; confirmar
                     condiciones) + transferencia/PSE para planes anuales.

  Archivos grandes: Vercel limita el tamaño de lo que se envía a sus funciones (alrededor de
  4.5 MB). Los ZIP de facturas se suben directo a Supabase Storage y una función los procesa
  desde ahí.

6.3 ESTRUCTURA DEL REPOSITORIO (monorepo con pnpm workspaces)
  apps/desktop       App Tauri + React
  apps/web           Next.js: sitio, cuenta del cliente, API
  packages/motor     Reglas contables + pruebas
  packages/ui        Componentes y tokens de diseño
  packages/shared    Tipos, esquemas zod, catálogos (PUC, municipios, impuestos)
  supabase/          Migraciones SQL, políticas RLS, datos semilla

6.4 PRINCIPIOS
  - El servidor es la fuente oficial; el PC trabaja con una copia local.
  - El mismo motor corre en ambos lados; el servidor revalida TODO lo que llega.
  - La base de datos tiene reglas de último recurso (partida doble, inmutabilidad) aunque el
    código falle.
  - Nada contable se borra ni se edita después de contabilizado: se anula con un reverso.
  - Los parámetros tributarios están versionados por año y se actualizan sin reinstalar.

8. REGLAS DEL MOTOR CONTABLE (no se pueden romper)
===============================================================================================

   1. Cada comprobante cumple: suma de débitos = suma de créditos > 0, con al menos dos líneas.
   2. Una línea tiene débito o crédito, nunca ambos; ningún valor es negativo.
   3. Solo las cuentas de movimiento (auxiliares) reciben líneas. Si la cuenta exige tercero o
      centro de costo, es obligatorio.
   4. No se contabiliza en períodos cerrados. Reabrir un período exige permiso y queda en
      auditoría.
   5. El consecutivo es único y sin huecos por tipo y empresa, y lo asigna SOLO el servidor al
      contabilizar.
   6. Un comprobante contabilizado es inmutable. Para corregirlo se anula con un comprobante de
      reverso que indica el motivo.
   7. Todo movimiento de inventario, cartera o bancos nace de un comprobante (trazabilidad).
   8. Redondeo en centavos exactos, con una política documentada para los impuestos (por línea o
      por total), igual a la del XML de la DIAN.
   9. El balance de prueba siempre cuadra; activo = pasivo + patrimonio (incluido el resultado del
      ejercicio).
  10. El cierre anual cancela las cuentas de resultado (clases 4, 5, 6 y 7) contra la cuenta de
      resultado del ejercicio y abre el nuevo año.

  RESPALDO EN POSTGRES
  - Un trigger rechaza comprobantes descuadrados al pasar a contabilizado.
  - Reglas que impiden modificar o borrar comprobantes contabilizados y registros de auditoría.
  - RLS por empresa en todas las tablas.


===============================================================================================
9. MODO SIN CONEXIÓN, SINCRONIZACIÓN Y FALLAS DE ENERGÍA
===============================================================================================

9.1 ESCRITURA
  - Toda operación se guarda primero en SQLite, dentro de una transacción, con un id único
    (UUID) y una clave de idempotencia.
  - Se agrega a la cola de salida con estado "pendiente".
  - Los comprobantes hechos sin conexión se muestran como "Pendiente de sincronizar", sin número
    oficial (por ejemplo "CG-LOCAL-7F3A").

9.2 ENVÍO
  - Cuando hay conexión, la app envía la cola en orden. El servidor valida con el mismo motor,
    asigna el consecutivo, contabiliza y responde.
  - Idempotencia: si un envío se repite (por ejemplo, un corte a mitad del envío), el servidor
    reconoce la clave y no lo duplica.
  - Si el servidor rechaza (período cerrado, sin permiso, descuadre, cuenta inactiva), el
    comprobante queda "Rechazado" con el motivo, para que el usuario lo corrija.

9.3 RECEPCIÓN
  - La app pide los cambios desde la última secuencia que conoce (sincronización incremental por
    empresa) y actualiza su copia local.
  - Primera instalación o PC nuevo: descarga inicial de la empresa con barra de progreso.

9.4 CONFLICTOS
  - Comprobantes: casi no hay conflictos, porque no se editan.
  - Datos maestros (terceros, productos, cuentas): gana el último cambio confirmado por el
    servidor. El cambio que pierde queda en auditoría y se avisa al usuario.
  - Inventario: las ventas sin conexión pueden dejar stock negativo; el servidor lo acepta pero
    genera una alerta (configurable).
  - Los saldos que la app muestra sin conexión llevan la marca "a la última sincronización
    (fecha y hora)".

9.5 FALLAS DE ENERGÍA
  - SQLite en modo WAL con synchronous=FULL: lo que se confirmó sobrevive a un apagón.
  - Autoguardado de formularios cada 3–5 segundos como borrador local.
  - Al iniciar la app: verificación de integridad (PRAGMA integrity_check). Si hay daño, se
    restaura el último respaldo local y se vuelve a sincronizar desde el servidor.
  - Respaldo local diario cifrado (se conservan los últimos 7) y exportación manual.
  - En el material de bienvenida, recomendar a los clientes una UPS.

9.6 FACTURACIÓN ELECTRÓNICA SIN CONEXIÓN (versión 2)
  - Sin internet no se puede validar ante la DIAN. Implementar el procedimiento de contingencia
    que defina la DIAN (confirmar con el asesor) y la transmisión posterior.

9.7 LÍMITES
  - Aviso visible si un equipo lleva más de 7 días sin sincronizar.
  - La app funciona sin conexión hasta un plazo definido (por ejemplo 30 días) antes de pedir que
    se valide la suscripción en línea.


===============================================================================================
10. SEGURIDAD Y PROTECCIÓN DE DATOS
===============================================================================================

  - Una cuenta por persona (no por rol), contraseña segura y MFA (TOTP) obligatorio para
    administradores.
  - Los permisos por empresa se aplican en el servidor (RLS). La app los replica solo para
    mostrar u ocultar opciones.
  - Base local cifrada (SQLCipher) con llave protegida por DPAPI. Al cerrar sesión, la llave se
    borra de la memoria.
  - Comunicación solo por HTTPS, con tokens de corta duración que se renuevan.
  - La IA local escucha solo en 127.0.0.1, en un puerto aleatorio y con un token por sesión.
  - Los secretos viven solo en el servidor. Nunca poner la llave service_role de Supabase en la
    app.
  - Auditoría inmutable de accesos y cambios.
  - Límite de intentos de inicio de sesión y de peticiones a la API.
  - Actualizaciones firmadas (el actualizador de Tauri verifica la firma antes de instalar).
  - Revisión de seguridad antes del piloto:
      - pruebas de RLS (el usuario A nunca ve la empresa B),
      - revisión de dependencias (npm audit, cargo audit),
      - revisión con la guía OWASP.
  - Respaldos: los diarios de Supabase + una exportación propia nocturna, cifrada, en otro

12. ASESOR DE IA LOCAL ("JARVIS")
===============================================================================================

12.1 PRINCIPIO: LA IA NO CALCULA
  Los modelos pequeños inventan cifras. El modelo entiende la pregunta en español, llama
  herramientas del motor contable y explica los resultados. Toda cifra que ve el usuario sale del
  motor, nunca del modelo.

12.2 COMPONENTES
  - Motor: llama.cpp (llama-server) como proceso auxiliar de Tauri, con API compatible con
    OpenAI en 127.0.0.1.
  - Modelo: formato GGUF cuantizado (Q4_K_M). Candidatos a probar: familia Qwen (licencia
    Apache 2.0, buen español y buen uso de herramientas) en tamaños de 4B y 8B parámetros.
    Compararlos con Gemma y Llama pequeños, revisando sus licencias para uso comercial. Se elige
    con la evaluación del punto 12.5.
  - Descarga: el modelo NO va dentro del instalador. Se descarga dentro de la app, de forma
    opcional (2–5 GB), reanudable y verificada con hash.
  - Niveles según el hardware (se detecta al instalar):
        Menos de 8 GB de RAM   -> IA desactivada; queda el asistente por reglas actual
        8 a 15 GB de RAM       -> modelo de ~3–4B parámetros
        16 GB o más            -> modelo de ~7–8B parámetros
        Con GPU compatible     -> aceleración opcional (Vulkan o CUDA)
  - El proceso de IA arranca cuando se necesita y libera la memoria tras unos minutos sin uso.

12.3 HERRAMIENTAS (funciones que el modelo puede llamar)
  saldo_cuenta, movimientos_cuenta, cartera_por_edades, cuentas_por_pagar, estado_resultados,
  balance_general, comparar_periodos, iva_periodo, retenciones_periodo, top_gastos,
  inventario_bajo, vencimientos_tributarios, buscar_tercero, buscar_comprobante,
  alertas_empresa.
  - Versión 1: solo lectura.
  - Versión 2: acciones con confirmación (por ejemplo, "crea el borrador del comprobante de
    nómina"), siempre como borrador que el contador revisa.

12.4 ALERTAS PROACTIVAS (las calculan reglas, no la IA)
  - Cartera vencida a más de 30, 60 y 90 días.
  - Pagos a proveedores próximos a vencer.
  - Vencimientos del calendario tributario de cada empresa (según el último dígito del NIT).
  - IVA estimado del período.
  - Descuadres y comprobantes rechazados.
  - Períodos sin cerrar.
  - Inventario bajo.
  - Facturas importadas sin contabilizar.
  - Gastos inusuales frente al promedio.
  La IA redacta el resumen: "Buenos días, esta semana tienes 3 vencimientos...".

12.5 EVALUACIÓN ANTES DE ELEGIR MODELO
  - Banco de 150 preguntas reales de contadores (del piloto), cada una con su respuesta esperada.
  - Metas:
        herramienta correcta elegida           90 % o más
        cifras correctas                       100 % (vienen de la herramienta)
        tiempo de respuesta en PC de 8 GB      menos de 10 segundos en respuestas cortas
        calidad del español                    revisión manual
  - Repetir la evaluación cada vez que cambie el modelo o las instrucciones.

12.6 NORMATIVA (fase posterior)
  - Biblioteca curada (Estatuto Tributario, decretos y resoluciones clave, calendario, NIIF para
    Pymes) dividida en fragmentos, con embeddings multilingües y sqlite-vec.
  - Respuestas con cita de la fuente y su fecha, y el aviso "orientación; no reemplaza el
    criterio del contador".
  - La biblioteca se actualiza desde el servidor. Los valores anuales (UVT, tarifas) vienen de
    parametros_anuales, nunca de la memoria del modelo.

12.7 VOZ (opcional, al final)
  whisper.cpp (voz a texto) y Piper (texto a voz, con voces en español), ambos locales.

12.8 PRIVACIDAD
  Nada sale del PC. Si algún día se usa un modelo en la nube, que sea solo con consentimiento
  explícito y en planes de pago del proveedor: los planes gratuitos pueden usar los datos para
  entrenar sus modelos.

  - Pruebas en Windows desde tu PC con Linux: máquina virtual con Windows (QEMU o VirtualBox) y
    un PC físico de gama baja (8 GB) para medir la IA.
  - Herramienta interna de soporte: ver el estado de sincronización de un cliente (colas,

20. RIESGOS Y MITIGACIONES
===============================================================================================

   1. Error contable o tributario del software (daña tu reputación y a los clientes).
      -> Contador asesor, casos de prueba, doble corrida en el piloto, cláusula de
         responsabilidad, parámetros actualizables.
   2. Cambios normativos (DIAN, UVT, reformas tributarias).
      -> Parámetros por año, actualizaciones obligatorias, seguimiento de las publicaciones de la
         DIAN, tiempo reservado para mantenimiento cada año.
   3. Pérdida o daño de datos.
      -> WAL, respaldos locales y en la nube, pruebas de restauración mensuales.
   4. Fallas de sincronización (documentos duplicados o perdidos).
      -> Idempotencia, pruebas de cortes, métricas de colas, herramienta de soporte.
   5. La IA inventa cifras o da una orientación equivocada.
      -> Solo herramientas para cifras, citas de fuentes, avisos visibles, evaluación continua.
   6. PC de clientes muy débiles.
      -> Niveles de IA, app ligera, requisitos mínimos publicados.
   7. SmartScreen o el antivirus bloquean el instalador.
      -> Firma de código, reputación con descargas, instrucciones claras.
   8. La competencia baja precios o copia funciones.
      -> Nicho definido, relación cercana con contadores, sin conexión + IA local.
   9. Todo depende de una sola persona.
      -> Documentación, código con pruebas, respaldo del repositorio, acuerdo con un
         desarrollador de apoyo.
  10. Demasiado soporte en temporadas altas.
      -> Base de conocimiento, videos, horario definido, soporte premium pagado.
  11. Robo de un PC o filtración de datos.
      -> Cifrado local, MFA, RLS, plan de incidentes.
  12. Falta de dinero antes de tener ingresos.
      -> Precio de fundador con pago anual anticipado de los pilotos y costos fijos bajos.
